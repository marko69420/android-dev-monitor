# Architecture

There are two front ends over one set of view models. `AndroidDevMonitor.App` is the Windows composition root (WPF) and `AndroidDevMonitor.Desktop` the Linux one (Avalonia); both build the same services and pass them to `MainViewModel`, which lives in `AndroidDevMonitor.Presentation` and has no UI-toolkit dependency. What differs per toolkit goes through `PlatformServices`: the UI dispatcher, dialogs, file pickers, clipboard, image decoding and app lifecycle. `DesktopShell` opens files, reveals them in the file manager and manages start-with-system on Windows (Run key), Linux (`~/.config/autostart`) and macOS. `FilteredCollection<T>` replaces WPF's `ICollectionView` for filtered and sorted lists. `MainViewModel` holds the one global selected-device context; code-behind only assigns the injected view model and handles pointer input such as mirror taps. The Core project owns stable records/interfaces and has no UI or ADB dependencies; `AppPaths` gives the data, documents and export folders for each OS. ADB owns executable resolution (`ToolLocator` finds adb, the emulator, build-tools and scrcpy on each OS), structured command results, per-serial concurrency gates, discovery, metadata and tolerant parsers. Collectors use those interfaces to produce the same immutable `MetricSample` and `AndroidProcess` models as demo mode. Infrastructure owns SQLite, media and exports.

On target change, the view model cancels and disposes the old context token, closes its session, clears transient package/device views, creates a new session, then launches metric/process/timer loops bound to the captured serial and session ID. Each callback rechecks both IDs, preventing late results from contaminating the next target.

Every local ADB process uses `ProcessStartInfo.ArgumentList`, redirected output, no shell window, timeout, cancellation, and a structured result. A keyed semaphore limits concurrent commands per device. Lightweight, process and heavy schedules come from `MonitoringConstants`; background results are marshalled to the UI dispatcher in bounded snapshots.

Samples are retained in fixed-window buffers for UI and accumulated in the active session. SQLite runs WAL mode and sample inserts are batched in transactions. Sessions, events, markers, alerts, settings, media metadata, and automation sequences are local. Session exports run asynchronously to JSON/CSV and ZIP. Application shutdown cancels collectors and persists the active session before disposing services.

Demo mode substitutes discovery, monitoring, and media services at dependency-injection composition time. It does not fork the UI/domain model and cannot accidentally invoke ADB.

The Linux app's bindings are compiled, so a property or command name that does not exist fails the build. `tests/AndroidDevMonitor.Desktop.Tests` runs the Linux app in Avalonia's headless platform with real Skia rendering: every page is rendered and checked for binding errors, and live-mode tests drive the app against `tests/fake-android`, a fake adb and Android device that runs `adb shell` commands locally and reads `/proc` from the real kernel.
